# Состояние

## Готово

Браузерная программа на React, TypeScript и Vite. Сервер, учётные записи и облако не нужны. Мечети хранятся в этом браузере и сохраняются сами.

Разделы: Мечеть, Расписание, Икамат, Рамадан, Праздники и объявления, Экспорт.

Можно загрузить таблицу Excel поддерживаемого вида, годовой JSON и календарь, править дни, задать икамат, Рамадан и объявления, проверить данные и скачать два файла для приложения Нур Ислам: `prayer-schedule-ГОД.json` и `mosque-calendar.json`. «Скачать всё» собирает их в архив с короткой памяткой. Есть отмена, копия проекта и несколько мечетей.

Учебные файлы с вымышленными временами: `examples/`. Как пользоваться: `docs/rukovodstvo.md`.

## Проверено

- `npm run typecheck`, `npm run lint` — без ошибок.
- Модульные проверки: 22 теста, все прошли. В них форматы, високосный год, икамат, календарь, копия проекта и таблица.
- Сценарии в браузере, Chrome: компьютер 1280×860 и телефон 390×844. Пустая мечеть и повторное открытие, плохой файл, копия проекта, таблица Казани без подмены города, путь «создать мечеть → загрузить → поправить минуту → скачать оба файла → загрузить снова → сверить минуты». Стрелки по таблице проверены на компьютере. На телефоне дни правятся карточкой, отдельная проверка стрелок там не нужна.
- `npm run build` собирает папку `dist`.
- Проверка GitHub Actions описана в `.github/workflows/ci.yml`. На этот черновик она запустится после отправки ветки. Публикация страницы сама не включается.

Таблица `tests/fixtures/kazan-2026.xlsx` — тот же очищенный корпус, что в тестах приложения (SHA-256 `7f57f7251508666d818c159a66c37b279917441f1d8a44876629d46e9006e192`): 365 дней × 8 времён, Иша 1 января 2026 — 18:50, в пояснении есть «730 сохранённых». Исходный файл `vremena_namazov_RT_2026_0.xlsx` на машине не было, его сверка не заявляется.

Парсеры приложения с коммита `df61bc1303521d2c6a8fc17c68c5984d8d9d4ddc` скомпилированы Kotlin 2.1.20 и Gson 2.11 во временной копии вне репозитория Android. Разобраны учебные JSON, файлы, которые скачал браузерный сценарий для «Мечеть Дружба» / Уфа (365 дней, схема 2, календарь принят вместе с расписанием), и очищенная таблица Казани (2920 значений). Для сборки вне Android оставлены только два типа, до которых разбор файлов не доходит: интерфейс хранилища расписания и настройки экрана. Сами `ScheduleJson`, `ScheduleXlsx` и `MosqueCalendarJson` — из этого коммита.

## Проблемы

- Файла `vremena_namazov_RT_2026_0.xlsx` нет. Проверена очищенная копия из тестов приложения, не исходная книга с этим именем.
- Набор тестов Gradle и установка на телевизор или телефон не запускались. Разбор файлов парсерами на JVM прошёл, импорт на устройстве — нет.
- Публичного адреса страницы нет. Сборка проверена локально.

## Осталось

- Владелец включает GitHub Pages и вручную запускает workflow «Страница», если нужен адрес в интернете.
- Слияние в `main` и выкладка на рабочий адрес — только после отдельного решения владельца.
- Если нужна сверка именно исходной книги `vremena_namazov_RT_2026_0.xlsx`, её надо дать отдельно.

## Что нужно владельцу

Не сливать этот черновик и не публиковать страницу, пока сами не решите. Учебный пример — не расписание для намаза. После публикации человек открывает адрес, создаёт мечеть, загружает свою таблицу и скачивает два файла. Данные из браузера посетителя на сервер не уходят.
